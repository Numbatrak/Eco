# GitHub Actions & Database Management

This repository uses GitHub Actions to automatically maintain and back up the Supabase database.

## Active Workflows

Both workflows can be triggered manually at any time from the **Actions** tab in GitHub.

### 1. Supabase Heartbeat (`supabase-heartbeat.yml`)

- **Purpose:** Prevents the Supabase free-tier project from pausing due to inactivity.
- **Schedule:** Runs daily at 12:00 UTC.
- **How it works:** Pings the Supabase REST API directly using the `SUPABASE_ANON_KEY` to simulate active database usage.

### 2. Automated DB Backup (`supabase-backup.yml`)

- **Purpose:** Creates a compressed, custom-format database dump and stores it securely in GitHub.
- **Schedule:** Runs every Sunday at 02:00 UTC (3:00 AM WAT).
- **Where to find backups:** Go to the **Actions** tab > click the latest **Supabase DB Backup** run > scroll down to **Artifacts** to download the `.zip` file.
- **Note:** The backup is executed inside a PostgreSQL 17 Docker container to match the Supabase server version.

## How to Restore a Backup

If you ever need to restore the database from one of the `.dump` files generated by the backup workflow, follow these steps:

1. Download the backup artifact `.zip` from the Actions tab and extract it to get `supabase_backup.dump`.
2. Open your terminal in the exact folder where the `.dump` file is located.
3. Run the following Docker command, replacing `"YOUR_DESTINATION_DB_URL"` with the connection string of the database you are restoring _into_:

\`\`\`bash
docker run --rm -v $(pwd):/workspace -w /workspace postgres:17 pg_restore -d "YOUR_DESTINATION_DB_URL" --clean --if-exists --single-transaction --no-owner --no-privileges supabase_backup.dump
\`\`\`

> **Important Connection String Note:** If your database password contains special characters (like `@`, `$`, `!`), you **must** URL-encode them in the connection string (e.g., replace `@` with `%40`, `$` with `%24`).

### Command Breakdown:

- \`docker run ... postgres:17\`: Runs the restore inside a temporary Postgres 17 container so you don't need Postgres installed locally.
- \`$(pwd)\`: Tells Docker to mount your **p**resent **w**orking **d**irectory.
  - _(Note: If you are using Windows Command Prompt, replace `$(pwd)` with `%cd%`. If you are using Windows PowerShell, replace it with `${PWD}`)_.
- \`--clean --if-exists\`: Drops existing database objects before restoring, giving you a clean slate.
- \`--single-transaction\`: Wraps the entire restore in one transaction. If it fails partway through, it safely rolls back without corrupting the database.
- \`--no-owner --no-privileges\`: Prevents permission errors when restoring to Supabase's managed Postgres environment since the default user is not a superuser.

---

## ⚠️ Important Note on Supabase Storage

This backup perfectly captures the Postgres database (all tables, rows, users in the auth schema, and metadata). **It does not contain physical files stored in Supabase Storage buckets** (e.g., uploaded profile pictures, PDFs). If this app uses Supabase Storage, the physical files must be backed up separately.
